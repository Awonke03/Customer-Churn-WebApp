# Continuum | Customer intelligence
A business decision workspace for 90-day retail inactivity risk, conditional future revenue, segmentation and campaign allocation. Training and evaluation are exclusively in the notebook; the app reads saved artifacts. The example is historical, denominated in GBP, and not a live company portfolio. UCI Online Retail II, Daqing Chen (2012), https://archive.ics.uci.edu/dataset/502/online+retail+ii, CC BY 4.0. Positive purchases only; returns excluded. Customer IDs pseudonymized for demonstration. No real personal identifiers should be uploaded.
 
Run training locally: pip install -r requirements-training.txt; jupyter nbconvert --to notebook --execute Continuum_Training.ipynb --output Continuum_Training.executed.ipynb. Then pytest -q; gunicorn app:app. GitHub Actions executes the notebook and publishes validated artifacts. Render blueprint path continuum/render.yaml, branch continuum-render. The build intentionally fails until the offline artifacts exist; no training or external secrets on Render. Upload CSV is request-only, not persisted. Campaign uplift, contribution margin and cost are user assumptions, not causal estimates. Customer value is conditional modelled 90-day purchase revenue, not full lifetime value. Local driver is a median-replacement sensitivity, not SHAP or a causal effect. Model results stay in notebook/report, not customer-facing navigation.
