# Loyaltics | Customer & Revenue Intelligence

Vercel Hobby portfolio deployment, with a CDN-served static interface and a Flask Python function. Import `Awonke03/Customer-Churn-WebApp`, set production branch `loyaltics-vercel` and root directory `continuum`. Framework preset Flask, default install/build settings, no environment variables or external API keys. Python 3.12. This is a personal, non-commercial historical-data demonstration. No training at build time or on requests. The trained bundle is already committed. The interface opens without running predictions; click Example portfolio, Score one customer, or Import customers followed by Score customers. 3,000 rows and 2 MB request limit; anonymised data only, no personal identifiers.

Training remains in the original notebook `Continuum_Training.ipynb` and the executed notebook `Continuum_Training.executed.ipynb`. See `models/report.json` for honest held-out metrics. The conditional revenue estimate underperforms the historical-spending baseline on test MAE, and is exploratory. Retention scenarios assume a uniform recovery rate, not experimentally established uplift. Data is historical UK retail in GBP; inactivity means no positive purchase in the next 90 days. Source: Daqing Chen, Online Retail II, UCI Machine Learning Repository, CC BY 4.0, https://archive.ics.uci.edu/dataset/502/online+retail+ii.

The original `continuum-render` branch remains available; this branch uses Vercel rather than Render. Internal directory and original notebook names were retained to preserve reproducibility. To test locally, install requirements and pytest then run `python -m pytest -q` and `flask --app app run` from continuum. Vercel deployment has not been performed by this repository.

The public dashboard opens on a pre-scored historical UK portfolio. All UI, CSV inputs and monetary outputs use ZAR, with a documented fixed illustrative conversion of 23 ZAR per GBP. The prediction API converts ZAR features back to the original GBP model units and converts outputs to ZAR; this is not training on South African customers or a live exchange rate. `python prepare_demo.py` produces the static CDN snapshot from the saved model without retraining. If unavailable, the app requests the identical live demo payload once.
